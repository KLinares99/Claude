# Runner

A minimal, Strava-style running PWA: record runs with live GPS, see your
route draw on the map in real time, get automatic mile splits, and review
everything in a clean activity feed with weekly stats, best efforts and
goals. All data stays on-device (localStorage) with export/import backup.

> Branded **Runner** — orange tile with an ascending route-line logomark
> (`src/components/Logo.tsx`, PNG icons generated by
> `scripts/generate-icons.mjs`).

## Screens
1. **Home** — weekly snapshot (distance / time / runs vs. goal, streak) and
   a Strava-style activity feed with route previews; tap an activity for the
   full map, stats and mile splits; manual logging for treadmill runs.
2. **Record** — live GPS run (map, time, distance, avg pace, calories,
   splits) plus an **Intervals** mode (run/walk workouts with a cadence
   metronome and audio cues).
3. **Nutrition** — MyFitnessPal-style daily diary: Goal − Food + Exercise =
   Remaining, with the exercise credit computed from your logged runs.
   Onboarding computes a personal calorie target (Mifflin-St Jeor BMR ×
   activity ± goal) and macro targets. Log food by searching the built-in
   ~150-food database, entering macros manually, or with the **AI
   nutritionist**: photograph or describe a meal and Claude estimates
   calories + macros per item and gives goal-aware tips. The AI is
   bring-your-own-key — the user's Anthropic API key is stored only
   on-device and requests go browser → api.anthropic.com directly (no app
   server). Everything except the AI works fully offline.
4. **You** — profile, all-time totals, 8-week mileage chart, best efforts
   (longest run, fastest mile, best avg pace), settings, data & backup.

A **quote / tip of the day** (365+ entries in `src/data/quotes.ts`, indexed
by day-of-year) greets you once per day when the app opens.

## Never-reset sessions (the important part)
The GPS tracker (`src/lib/tracker.ts`) and interval timer
(`src/lib/intervals.ts`) are **module-level singletons that live outside
React**. Screens only *subscribe* to them, so switching tabs never resets
the timer, the route or the map. On top of that:
- The Record screen stays mounted for the whole app session (hidden with
  CSS), so the Leaflet map instance is never destroyed.
- Timing is wall-clock based (accumulated active milliseconds), immune to
  background-tab timer throttling.
- The in-progress run is snapshotted to localStorage and recovered (paused)
  after a page reload.
- A live banner appears over the nav while recording on another tab.

## Stack
- **React + Vite + TypeScript**, Tailwind, Leaflet (OpenStreetMap tiles),
  Recharts, lucide-react
- **PWA**: web manifest, service worker (offline app shell), installable
- **Wake Lock API** keeps the screen on while recording
- **Web Audio** metronome + cue beeps via a lookahead scheduler
- **localStorage** store (`runner:v1`); legacy `forge:v1` data is migrated
  automatically on first load

## Data model (`runner:v1`)
```
{ activities: [{ id, date, name, seconds, miles, route[], splits[], source, note }],
  settings: { name, weightLbs, weeklyGoalMiles, runBpm, walkBpm } }
```

## Couple sync (optional server)
The shared feed is powered by a free Supabase project you own. Runs sync to
it (cross-device backup) and a linked partner sees your runs — with kudos —
on their Home feed. Nutrition data never syncs; it stays on each device.

One-time setup (~5 minutes, one of you does it):
1. Create a free project at **supabase.com** (any name/region).
2. In the dashboard, open **SQL Editor → New query**, paste the entire
   contents of [`supabase/schema.sql`](supabase/schema.sql), and Run.
3. In **Authentication → Sign In / Providers → Email**, turn OFF
   "Confirm email" so phone signups are instant.
4. In **Project Settings → API**, copy the **Project URL** and the
   **anon public** key.
5. In the app, go to **You → Couple sync**, paste both values, create your
   accounts (one each), then one of you enters the other's 6-character
   invite code. Done — the feed is shared.

The anon key is safe to share between your two phones (it's public by
design); row-level security in the schema is what keeps each account's
writes to itself. To skip the paste step entirely, bake the two values into
`DEFAULTS` in `src/lib/sync.ts` and redeploy.

### Friends upgrade (usernames + follows + workout sharing)
To enable the **You → Friends** card (claim a @username, follow friends,
and share runs *and* workouts in the feed), run one more SQL file on the
same project: **SQL Editor → New query**, paste the entire contents of
[`supabase/schema_v2_friends.sql`](supabase/schema_v2_friends.sql), and
Run. Safe to re-run; existing couple links keep working unchanged.

## Develop
```bash
npm install
npm run dev      # vite dev server
npm run build    # tsc + vite build -> dist/
npm run preview  # serve the production build (base path /Claude/)
npm run icons    # regenerate PWA icons into public/
```

## Deploy
GitHub Pages via `.github/workflows/deploy.yml` (base path `/Claude/`).

## Notes
- Mobile browsers stop GPS when the screen locks; the wake lock mitigates
  this while the app is foregrounded. True background tracking needs a
  native wrapper (e.g. Capacitor) — a good next step.
